MPRINT integration and validation

MPRINT direct-data integration completed November 17, 2026.
New tools: search_mprint_gold(drug,max_results=10) and get_mprint_silver_classifications(pmids). MCP now exposes 16 tools, 3 prompts and 1 resource. Existing search_mprint remains the clearly labeled PubMed/RePORTER keyword-search route; new tools query actual published MPRINT exports.
Data scope: Gold includes 3,822 study-metadata rows from PK and PE/clinical-trial tables (not necessarily distinct papers). Silver includes 1,310,622 PMID/classification entries (not necessarily distinct papers) across PK, PE, CT, Biomarker, Vaccine, and Food/nutrition/other categories. Gold is expert-curated metadata; Silver labels are automated. Outcome and PK-parameter tables, Silver drug/population mappings, and live portal state are not included. This is a versioned snapshot, not a live MPRINT API. Published dataset revision: 4bdee90dff3610816e86d0eed29b4c4d0fe76e89. MIT license retained in package; source-file hashes and retrieval time recorded.
Architecture: mc/mprint_data.py opens a bundled SQLite database read-only; Gold uses whole-token matches on curated drug names, Silver uses indexed parameterized PMID lookups. Requests do not write the database or require additional paid compute. Gold results retain source fields, source file/row, PMID links and dataset revision. No synonym mapping or publication-date sorting is claimed. Silver may return multiple labels; missing results are not evidence of an absence of research. Inclusion does not imply efficacy, safety, quality or MPRINT funding. Use get_abstracts to retrieve underlying study evidence.
Validation: 63 unit tests passed, including 14 new validation/search/read-only/provenance tests; all 13 deployed smoke checks passed, covering existing tools, FDA pediatric tool, Gold positive/negative searches and Silver positive/negative/multiple-label lookups. Final chat invoked both new tools, preserved Gold/Silver distinction, cited revision/source files and did not infer safety or efficacy.
Deployment fixes: initial 81.5 MB SQLite file exceeded Databricks' 50 MB per-file export limit. Rebuilt Silver table WITHOUT ROWID and vacuumed to 37,961,728 bytes, preserving entry count and passing SQLite integrity_check. A client test then caught duplicate-case response keys; original column names were moved into source_fields and a regression assertion added. Final deployment: 01f1e2c8874210f2991be5ee073445ed. No new compute or permissions.
Refresh: run the companion build-mprint-snapshot.py with an explicitly selected upstream revision, review manifest/schema/count changes, rerun tests and deploy. Refresh is not scheduled or automatic. The builder is outside the deployed app; no user request triggers downloads or updates.
