MCP-MC evaluation results

November 17, 2026. Two prompt variants, ten development questions each. MLflow judges score captured answers; they do not independently certify clinical accuracy.

Method

The same deployed MCP server and model endpoint answered a fixed source-backed question set using minimal or production system instructions. Exact first-line answers were checked against predeclared accepted values. Databricks MLflow then scored full responses for expected-fact correctness, safety, relevance and conciseness. This is answer-sheet evaluation; detailed MCP tool traces are retained separately. The dataset, prompts, source snapshots, deployment ID and installed package versions are saved with the local evaluation files.

Review of judge findings

All 100 scorer entries returned assessments; there were no scorer errors in the two full runs. There were 14 negative assessments: three correctness and eleven conciseness.
Correctness: both variants were marked down on G02 because the answer did not explicitly say undetectable concentrations are not a safety guarantee. Production was also marked down on G09 for not explicitly saying trial registration is not proof of benefit. The requested short answers were correct. Those caveats were in the expected-facts rubric but not explicit requests in the questions; align question and rubric in a new version before treating omissions as substantive answer failures.
Judge consistency: minimal G09 was accepted despite the same omitted registration caveat. Repeated disclaimers were accepted in some responses and rejected in others. Preserve these rationales and manually adjudicate; do not infer clinical accuracy or prompt superiority from the aggregate scores.
Independent source review still flagged G06 production's compressed case-report timeline; the correctness judge accepted its expected ingredient fact. This demonstrates why checking expected facts alone can miss extra unsupported detail. No answer key or judge rule was changed in response to these scores.

Interpretation and limits

Both variants obtained 10/10 deterministic short-answer matches. Correct first-line values do not guarantee every extra explanation is correct. G06 production compresses a source timeline and remains flagged for human/source review regardless of judge verdict. G09 required only one tool call; nine questions were multi-tool. Strengthen this task in the next version, and create a separate held-out set. This set draws on sources examined during development, has one execution per question per arm, and is neither a blind clinical evaluation nor statistically conclusive evidence that one prompt is better. A managed judge can miss errors; inspect its rationale rather than treating a score as certification.

Security and performance scope

Tests use synthetic questions and public sources. Credentials stayed in memory or existing CLI authentication; none were embedded in the notebook. No service principal or new compute was created. Earlier tests covered selected input validation, exception/log redaction and source-failure handling, not a complete security audit. Per-case timings and model usage are in the captured traces; concurrent traffic and caching limit performance comparisons.

Submission work still needed

Have a subject-matter reviewer check the answer key and flagged explanations; strengthen and freeze a held-out set; rerun after any final change; consolidate this report with prior regression results; and prepare the final evaluation document, repository instructions and demonstration slides. No clinical certification is claimed or required by the reviewed hackathon materials.
