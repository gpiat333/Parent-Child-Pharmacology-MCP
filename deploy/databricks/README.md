# Databricks: tests and future deployment

The current revision was prepared and evaluated without deploying the App. The existing sandbox app remains on its earlier .9 deployment. Model calls and MLflow evaluation use the existing authorized workspace/profile. See the current evaluation report for exact local-versus-remote execution and job receipts.

For a future explicitly authorized deployment, stage only `src/`, root `main.py`, root `requirements.txt` and `server/requirements.lock`, plus this `app.yaml` at the staging root. Install from the root requirements. Root main.py explicitly adds its adjacent src directory, so staged startup does not depend on an editable install; an isolated-entrypoint test covers this boundary. Configure MCP_AUTH_PUBLIC_KEY (public RSA key, never private), MCP_AUTH_ISSUER and MCP_AUTH_AUDIENCE for an operator-managed RS256 access-token issuer. Every client token needs mcp:connect plus individual tool:<name> scopes. A gateway token alone is insufficient. Remote startup intentionally fails without this configuration. Key rotation requires updating configuration and restarting the application. No issuer, credentials or App deployment were created in this revision. The platform port selects HTTP; maintain authenticated gateway access and restricted user sharing. Configure `MCP_ALLOWED_HOSTS` with the assigned hostname if the platform does not supply `DATABRICKS_APP_URL`. Never disable DNS-rebinding protection to make a deployment pass. Keep `.env`, tests, artifacts, eval captures and developer directories out of staging. No deploy script or CI job runs automatically.

The retired server-only bundle and App descriptors were removed; their historical copies remain in Git history. They must not be used with the migrated source layout. The current package is rooted at repository level. Revalidate the deployment manifest, identity, allowed hosts, network policy and Python 3.13 support in the target environment before any deployment.

For tests, `eval/run.py` supports local MCP plus Databricks AI Gateway/MLflow. A one-time serverless notebook can test an uploaded frozen source archive in an isolated workspace directory, without changing the App. Test uploads contain only public data and source. The job receipt must distinguish actual notebook execution from local drivers that merely use Databricks models or tracking.
